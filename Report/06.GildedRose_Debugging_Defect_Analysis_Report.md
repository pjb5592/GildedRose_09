# Gilded Rose 디버깅 및 결함 분석 보고서

작성일: 2026-05-19

## 1. 보고서 목적

본 보고서는 C++17, Google Test 기반 Gilded Rose 프로젝트의 `ctest` 결과와 `GildedRose::updateQuality()` 구현을 QA 관점에서 점검한 내용을 정리한다.

분석 요청 항목은 다음과 같다.

- `EXPECT_EQ` 실패의 기대값/실제값 차이 요약
- `updateQuality()` 버그 위치 특정
- 결함 심각도 분류
- `Item` 구조체를 수정하지 않는 최소 변경 방안
- VS Code에서도 테스트 가능한 워크스페이스 설정 추가
- `cmake --build build && ctest` Green 확인 절차 제시

## 2. 분석 대상

검토 대상 파일은 다음과 같다.

- `cpp/src/GildedRose.cpp`
- `cpp/test/GildedRoseTest.cpp`
- `.vscode/settings.json`

`Item` 구조체와 public 인터페이스는 변경하지 않았다.

## 3. 실패 로그 및 EXPECT_EQ 차이 요약

요청 본문에는 실제 `ctest` 실패 로그가 포함되지 않았다.

현재 로컬 기준으로 다음 명령을 실행한 결과, 27개 테스트가 모두 통과했다.

```bash
cmake --build build
ctest --test-dir build --output-on-failure
```

검증 결과는 다음과 같다.

- 전체 테스트 수: 27개
- 실패 테스트 수: 0개
- `EXPECT_EQ` 실패: 없음
- 기대값/실제값 차이: 재현되지 않음

## 4. updateQuality() 결함 위치 분석

현재 `cpp/src/GildedRose.cpp`의 `updateQuality()`는 아이템별 규칙을 다음 방식으로 처리한다.

- `Sulfuras`는 즉시 `continue` 처리하여 `sellIn`, `quality`를 변경하지 않는다.
- `originalSellIn`을 보관한 뒤 `sellIn`을 하루 감소시킨다.
- `Aged Brie`는 판매 기한 경과 여부에 따라 1 또는 2 증가한다.
- `Backstage Pass`는 남은 날짜 구간에 따라 1, 2, 3 증가하거나 공연 이후 0이 된다.
- `Conjured` 접두어 아이템은 일반 아이템의 2배 속도로 감소한다.
- 일반 아이템은 판매 기한 경과 전 1, 경과 후 2 감소한다.
- 품질 하한과 상한은 `increaseQuality()`, `decreaseQuality()`에서 보정한다.

현재 테스트 기준으로 특정 가능한 버그 위치는 없다.

## 5. 결함 심각도

심각도는 `Info`로 분류한다.

근거는 다음과 같다.

- 실패 로그가 제공되지 않았다.
- 로컬에서 전체 Google Test 27개가 모두 통과했다.
- `Item` 구조체 수정 없이 현재 구현이 명세 테스트를 만족한다.
- 사용자 영향이 있는 재현 가능한 결함이 확인되지 않았다.

## 6. 최소 변경 수정 방안

현재 C++ 구현에는 추가 수정이 필요하지 않다.

실제 코드 변경은 VS Code 테스트 실행 편의를 위한 `.vscode/settings.json` 추가로 제한했다.

```json
{
  "cmake.sourceDirectory": "${workspaceFolder}/cpp",
  "cmake.buildDirectory": "${workspaceFolder}/build",
  "cmake.configureOnOpen": true,
  "cmake.ctestArgs": [
    "--output-on-failure"
  ]
}
```

이 설정은 CMake Tools가 `cpp/CMakeLists.txt`를 소스 디렉터리로 사용하고, 기존 루트 `build` 디렉터리에서 빌드 및 CTest를 실행하도록 맞춘다.
