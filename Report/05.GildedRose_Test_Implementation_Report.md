# Gilded Rose 테스트 구현 결과 보고서

작성일: 2026-05-19

## 1. 보고서 목적

본 보고서는 C++17, Google Test 기반 Gilded Rose 프로젝트에서 수행한 아이템 타입별 단위 테스트 작성 및 구현 보강 결과를 정리한다.

작업 목표는 `GildedRose::updateQuality()`의 핵심 도메인 규칙을 `TEST_F` 기반 테스트로 보호하고, `Normal`, `Aged Brie`, `Backstage Pass`, `Sulfuras`, `Conjured` 아이템의 경계값 동작을 검증하는 것이다.

## 2. 작업 대상

수정 및 검토 대상 파일은 다음과 같다.

- `cpp/test/GildedRoseTest.cpp`
- `cpp/src/GildedRose.cpp`
- `cpp/include/GildedRose.h`
- `docs/requirements_analysis.md`

`Item` 클래스와 `GildedRose` public 인터페이스는 변경하지 않았다.

## 3. 테스트 구현 요약

기존 `cpp/test/GildedRoseTest.cpp`의 기본 실패 테스트를 제거하고, `GildedRoseItemRulesTest` 픽스처 기반의 명세 테스트로 교체했다.

테스트는 다음 기준을 따른다.

- 모든 테스트는 Google Test의 `TEST_F`를 사용한다.
- 각 테스트는 `Given`, `When`, `Then` 주석 구조를 가진다.
- `sellIn`과 `quality`는 `EXPECT_EQ`로 명시적으로 검증한다.
- 아이템 타입별 최소 5개 이상의 테스트를 작성했다.
- `quality == 0`, `quality == 50`, `sellIn == 0`, `sellIn == -1` 경계값을 포함했다.

최종 테스트 수는 총 27개이다.

## 4. 아이템 타입별 검증 범위

### 4.1 Normal

Normal 아이템은 총 5개 테스트로 검증했다.

- 판매 기한 전 하루 경과 시 `sellIn`은 1 감소하고 `quality`는 1 감소한다.
- 호출 전 `sellIn == 0`이면 호출 후 판매 기한 경과 규칙이 적용되어 `quality`가 총 2 감소한다.
- 호출 전 `sellIn == -1`이면 이미 기한이 지난 상태로 보고 `quality`가 2 감소한다.
- `quality == 0`에서는 더 이상 감소하지 않는다.
- 감소량이 현재 `quality`보다 커도 결과는 0 미만으로 내려가지 않는다.

### 4.2 Aged Brie

`Aged Brie`는 총 5개 테스트로 검증했다.

- 판매 기한 전 하루 경과 시 `quality`가 1 증가한다.
- 호출 전 `sellIn == 0`이면 `quality`가 총 2 증가한다.
- 호출 전 `sellIn == -1`이면 `quality`가 2 증가한다.
- `quality == 50`에서는 더 이상 증가하지 않는다.
- 기한 경과 후 증가량이 2여도 `quality`는 50을 초과하지 않는다.

### 4.3 Backstage Pass

`Backstage Pass`는 총 6개 테스트로 검증했다.

- `sellIn > 10`이면 `quality`가 1 증가한다.
- `sellIn == 10`이면 `quality`가 2 증가한다.
- `sellIn == 5`이면 `quality`가 3 증가한다.
- 증가 후에도 `quality`는 50을 초과하지 않는다.
- 호출 전 `sellIn == 0`이면 공연이 지난 상태가 되어 `quality`가 0이 된다.
- 호출 전 `sellIn == -1`이면 `quality`가 계속 0으로 유지된다.

### 4.4 Sulfuras

`Sulfuras`는 총 5개 테스트로 검증했다.

- 판매 기한 전에도 `sellIn`과 `quality`가 변경되지 않는다.
- 호출 전 `sellIn == 0`이어도 값이 변경되지 않는다.
- 호출 전 `sellIn == -1`이어도 값이 변경되지 않는다.
- 일반 품질 상한 50 보정의 영향을 받지 않고 `quality == 80`을 유지한다.
- 비표준 품질값으로 전달되어도 `Sulfuras`는 입력된 값을 그대로 유지한다.

### 4.5 Conjured

`Conjured`는 총 6개 테스트로 검증했다.

- 판매 기한 전 하루 경과 시 `quality`가 2 감소한다.
- 호출 전 `sellIn == 0`이면 `quality`가 총 4 감소한다.
- 호출 전 `sellIn == -1`이면 `quality`가 4 감소한다.
- `quality == 0`에서는 더 이상 감소하지 않는다.
- 감소량이 현재 `quality`보다 커도 결과는 0 미만으로 내려가지 않는다.
- `"Conjured"` 접두어를 가진 이름은 Conjured 규칙으로 처리한다.

## 5. 구현 보강 내용

테스트를 Green으로 만들기 위해 `cpp/src/GildedRose.cpp`의 `updateQuality()` 구현을 요구사항에 맞게 보강했다.

주요 변경 사항은 다음과 같다.

- 품질 하한과 상한을 `kMinimumQuality`, `kMaximumQuality` 상수로 분리했다.
- `Aged Brie`, `Backstage Pass`, `Sulfuras`, `Conjured` 식별 문자열을 상수화했다.
- `increaseQuality()`, `decreaseQuality()` 헬퍼 함수로 품질 범위 보정을 일관되게 처리했다.
- `Sulfuras`는 가장 먼저 처리해 `sellIn`과 `quality`가 변경되지 않도록 했다.
- `Conjured`는 `"Conjured"` 접두어 기준으로 판별하도록 했다.
- `sellIn == 0`은 하루 경과 후 판매 기한이 지난 것으로 보고 경과 후 규칙을 적용했다.

## 6. 검증 결과

빌드 및 테스트는 다음 명령으로 확인했다.

```bash
cmake --build build
ctest --test-dir build --output-on-failure
```

추가로 `build` 디렉터리에서 다음 명령도 실행했다.

```bash
cmake --build .
ctest --output-on-failure
```

검증 결과는 다음과 같다.

- 빌드 성공
- 전체 테스트 27개 실행
- 실패 테스트 0개
- 최종 결과: `100% tests passed, 0 tests failed out of 27`

참고로 저장소 루트에서 `ctest`만 실행하면 현재 CTest 설정 파일이 루트에 없기 때문에 `No test configuration file found` 메시지가 출력된다.
따라서 이 프로젝트에서는 `ctest --test-dir build`를 사용하거나 `build` 디렉터리로 이동한 뒤 `ctest`를 실행해야 한다.

## 7. 결론

이번 작업으로 기존 실패 테스트를 제거하고, 요구사항 기반의 아이템 타입별 단위 테스트를 구축했다.
각 테스트는 경계값과 판매 기한 전후 동작을 명확히 검증하므로 이후 리팩토링 시 회귀를 탐지할 수 있는 안전망으로 사용할 수 있다.

또한 `Conjured` 신규 요구사항을 구현에 반영해 테스트와 실제 동작이 일치하도록 만들었다.
현재 기준으로 `GildedRose::updateQuality()`의 주요 도메인 분기는 Google Test로 보호되며, 전체 테스트는 Green 상태이다.
