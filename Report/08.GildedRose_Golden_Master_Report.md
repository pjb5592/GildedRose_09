# Gilded Rose Golden Master 회귀 테스트 보고서

작성일: 2026-05-19

## 1. 보고서 목적

본 보고서는 C++17, Google Test, CMake 기반 Gilded Rose 프로젝트에 TexttestFixture 출력 기반 Golden Master(Approval) 회귀 테스트를 설계·구현한 결과를 정리한다.

작업 목표는 다음과 같다.

- TexttestFixture와 동일한 시뮬레이션 출력을 기준으로 전체 동작 회귀를 탐지한다.
- 단위 테스트(27개)와 별도로 31일 × 5아이템 시나리오를 한 번에 검증한다.
- CMake `ctest`와 GitHub Actions CI에 통합한다.

## 2. 작업 대상

추가·수정된 파일은 다음과 같다.

| 구분 | 경로 |
|------|------|
| 시뮬레이터 헤더 | `cpp/include/TexttestSimulator.h` |
| 시뮬레이터 구현 | `cpp/src/TexttestSimulator.cpp` |
| Texttest CLI | `cpp/src/TexttestFixture.cpp` |
| Golden Master 테스트 | `cpp/test/GoldenMasterTest.cpp` |
| Approved 출력 | `cpp/test/golden/texttest_31_days.expected.txt` |
| 빌드 설정 | `cpp/CMakeLists.txt` |
| CI 워크플로 | `.github/workflows/cpp-tests.yml` |

`Item` 클래스와 `GildedRose` public 인터페이스는 변경하지 않았다.

## 3. Golden Master 설계 요약

### 3.1 Expected 출력 보관 전략

- **저장 위치**: `cpp/test/golden/texttest_31_days.expected.txt` (소스 트리, Git 버전 관리)
- **출력 형식**: Texttest 표준 (`OMGHAI!` → 초기 인벤토리 → `-------- day N --------`)
- **시뮬레이션 범위**: 31일, 클래식 인벤토리 5종
- **줄바꿈**: LF 기준 저장, 비교 시 CRLF→LF 정규화
- **실패 시**: `texttest_31_days.received.txt` 자동 생성 (`cpp/test/golden/.gitignore`로 제외)
- **갱신**: 의도된 동작 변경 시에만 `update-golden-master` 또는 `UPDATE_GOLDEN=1`

### 3.2 공유 시뮬레이션 구조

`TexttestSimulator`에 시뮬레이션 로직을 한 곳에 모았다.

- `createTexttestItems()`: 클래식 5아이템 초기화
- `runTexttestSimulation(days)`: 전체 출력 문자열 생성
- `texttest_fixture`: Texttest 호환 실행 파일 (일 수 인자, 기본 2)
- `gilded_rose_golden_test`: GTest에서 동일 함수 호출 후 파일 비교

### 3.3 Google Test 비교 방식

`GoldenMasterTest.ThirtyOneDayTexttestOutputMatchesApprovedFile` 테스트가 다음을 수행한다.

1. `runTexttestSimulation(31)` 실행
2. `texttest_31_days.expected.txt` 읽기
3. 전체 문자열 일치 여부 검증
4. 불일치 시 `received` 파일 기록 후 실패 메시지 출력

## 4. CMake / ctest 통합

`cpp/CMakeLists.txt`에 추가된 타깃:

| 타깃 | 역할 |
|------|------|
| `texttest_simulator` | 공유 시뮬레이션 정적 라이브러리 |
| `texttest_fixture` | Texttest 호환 콘솔 실행 파일 |
| `gilded_rose_golden_test` | Golden Master GTest 실행 파일 |
| `update-golden-master` | approved 파일 재생성 커스텀 타깃 |

`gtest_discover_tests`로 단위 테스트 27개와 Golden Master 1개가 `ctest`에 등록된다.

## 5. CI 구성

`.github/workflows/cpp-tests.yml`에서 다음 매트릭스로 자동 실행한다.

- OS: `ubuntu-latest`, `windows-latest`
- Build type: `Debug`, `Release`

각 job은 `cpp` 디렉터리에서 configure → build → `ctest --output-on-failure` 순으로 실행한다.

## 6. 검증 결과

다음 명령으로 검증했다.

```powershell
cd cpp
cmake -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build
ctest --test-dir build --output-on-failure
```

검증 결과:

- 빌드: 성공
- 전체 테스트: 28개 (단위 27 + Golden Master 1)
- 실패: 0개
- 최종 결과: `100% tests passed, 0 tests failed out of 28`

Golden Master approved 파일은 `update-golden-master` 타깃으로 현재 구현 기준 출력을 생성했다.

## 7. 실행 방법

### 전체 테스트

```powershell
cd cpp
cmake -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build
ctest --test-dir build --output-on-failure
```

### Golden Master만 실행

```powershell
.\build\gilded_rose_golden_test.exe --gtest_filter=GoldenMasterTest.*
```

### TexttestFixture 수동 확인 (31일)

```powershell
.\build\texttest_fixture.exe 31
```

### Approved 출력 갱신 (의도된 변경 시에만)

```powershell
cmake --build build --target update-golden-master
```

## 8. 단위 테스트와의 역할 분담

| 테스트 유형 | 검증 범위 | 목적 |
|-------------|-----------|------|
| 단위 테스트 (`GildedRoseTest.cpp`) | 아이템 타입별 규칙, 경계값 | 요구사항 명세, 리팩토링 안전망 |
| Golden Master | 31일 전체 시나리오 출력 | 통합 회귀, TexttestFixture 호환성 |

리팩토링 시 권장 순서:

1. 단위 테스트 Green 유지
2. Golden Master 실행
3. 실패 시 `received` vs `expected` diff 검토
4. 의도된 변경이면 `update-golden-master`로 approved 갱신

## 9. 결론

TexttestFixture 출력 기반 Golden Master 회귀 테스트를 도입해, Gilded Rose의 전체 시뮬레이션 동작을 단일 승인 파일로 보호할 수 있게 되었다.

단위 테스트가 규칙·경계값을 세밀하게 검증하는 반면, Golden Master는 31일 × 5아이템 통합 시나리오의 회귀를 한 번에 탐지한다. CMake `ctest`와 GitHub Actions CI에 통합되어 로컬과 원격 환경 모두에서 동일한 검증을 자동 실행할 수 있다.
