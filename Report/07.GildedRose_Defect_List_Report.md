# Gilded Rose 결함 목록 문서화 보고서

작성일: 2026-05-19

## 1. 보고서 목적

본 보고서는 QA 리드 관점에서 현재까지 발견된 테스트 실패와 결함을 `docs/defect_list.md`에 정리한 결과를 기록한다.

문서화 목표는 각 결함을 다음 공통 형식으로 추적 가능하게 남기는 것이다.

- `[ID]`
- `[Severity]`
- `[ItemType]`
- `[Steps]`
- `[Expected]`
- `[Actual]`
- `[Root Cause]`
- `[Fix Summary]`

## 2. 산출물

생성한 결함 목록 파일은 다음과 같다.

- `docs/defect_list.md`

해당 문서는 Markdown 형식으로 작성했으며, 결함별 재현 절차와 기대 결과, 실제 결과, 원인, 수정 요약을 한글로 정리했다.

## 3. 정리된 결함

총 4개 항목을 문서화했다.

### 3.1 DEF-001

- 심각도: `Major`
- 아이템 타입: `Test`
- 요약: 초기 placeholder 테스트인 `GildedRoseTest.Foo`가 `"fixme"`를 기대해 실패하던 문제
- 수정 요약: placeholder 테스트를 제거하고 요구사항 기반 `GildedRoseItemRulesTest` 명세 테스트로 교체

### 3.2 DEF-002

- 심각도: `Major`
- 아이템 타입: `Conjured`
- 요약: `Conjured` 아이템이 판매 기한 전 일반 아이템처럼 하루 `-1`만 감소할 수 있던 문제
- 수정 요약: `Conjured` 접두어 판별 및 판매 기한 전 `quality -2` 규칙 구현

### 3.3 DEF-003

- 심각도: `Major`
- 아이템 타입: `Conjured`
- 요약: `sellIn == 0` 또는 판매 기한 경과 후 Conjured 감소량이 하루 `-4`로 적용되지 않을 수 있던 문제
- 수정 요약: `originalSellIn <= 0` 조건에서 Conjured 감소량을 `4`로 적용하고 경계값 테스트 추가

### 3.4 DEF-004

- 심각도: `Minor`
- 아이템 타입: `TestEnvironment`
- 요약: VS Code에서 CMake 소스/빌드 디렉터리와 CTest 옵션이 명확히 고정되어 있지 않던 문제
- 수정 요약: `.vscode/settings.json`에 `cmake.sourceDirectory`, `cmake.buildDirectory`, `cmake.ctestArgs` 추가

## 4. 현재 상태

최신 구현 기준으로 다음 검증은 Green 상태이다.

```bash
cmake --build build
ctest --test-dir build --output-on-failure
```

확인된 결과는 `27/27` 테스트 통과이며, 현재 재현되는 테스트 실패는 없다.

## 5. 참고 사항

VS Code CMake Tools 실행 과정에서 `build/` 하위의 CMake API 및 테스트 로그 파일이 갱신될 수 있다. 이번 업로드 요청은 모든 변경 파일을 대상으로 하므로 해당 생성 파일도 Git 상태 확인 대상에 포함했다.
