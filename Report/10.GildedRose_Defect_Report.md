# Gilded Rose 결함 관리 보고서

작성일: 2026-05-19

## 1. 보고서 목적

본 보고서는 QA 리드 관점에서 Gilded Rose 프로젝트의 **결함 분류·보고·품질 메트릭·(선택) GitHub Issues 연동** 체계를 `docs/defect_report.md`에 정의한 결과를 기록한다.

문서화 목표는 다음과 같다.

- Severity(Critical/Major/Minor/Info)와 ItemType 5종(Normal, AgedBrie, BackstagePass, Sulfuras, Conjured)의 **분류 매트릭스** 확립
- 결함 1건당 **재현·기대·실제·원인·수정·검증** 템플릿 표준화
- 테스트 통과율·커버리지·단계별 결함 발견율 **수집 계획** 수립
- (선택) GitHub Issues 라벨·워크플로우 가이드 제공

## 3. 결함 분류 체계 요약

### 3.1 Severity

| Severity | 요약 |
|---|---|
| Critical | 핵심 규칙·데이터 무결성 파괴, 배포 차단 |
| Major | 요구사항 미충족·P0/P1 테스트 Red |
| Minor | 제한적 조건·우회 가능, 유지보수성 저하 |
| Info | 기술 부채·개선 제안, 릴리스 게이트 제외 |

### 3.2 ItemType (5종)

도메인 결함은 Normal, AgedBrie, BackstagePass, Sulfuras, Conjured로 분류한다. 테스트·빌드 환경 결함은 `Test`, `TestEnvironment` 태그로 별도 추적한다.

### 3.3 Severity × ItemType 매트릭스

`docs/defect_report.md` §1.3에 전체 매트릭스와 비도메인 태그 참고표를 정의했다. QA는 신규 결함 등록 시 해당 표에서 전형적 영향·대응 수준을 참조한다.

## 4. 결함 보고서 템플릿

§2 템플릿 필드:

- 재현 (Reproduce): 전제·입력·명령·`updateQuality()` 호출 횟수
- 기대 (Expected) / 실제 (Actual)
- 원인 (Root Cause) / 수정 (Fix Summary)
- 검증 (Verification): 단위 테스트·`ctest`·커버리지·골든마스터 체크리스트

기등록 결함 DEF-001~004는 `defect_list.md`에 상세 기록되어 있으며, `defect_report.md` §2.1 요약 표와 연결된다.

## 5. 품질 메트릭 수집 계획

| 메트릭 | 목표 (C++ 본 저장소) |
|---|---|
| 테스트 통과율 | 100% (P0·P1) |
| 라인 커버리지 (`GildedRose.cpp`) | ≥ 90% |
| 브랜치 커버리지 | ≥ 85% |
| 단계별 결함 발견율 | RQ / UT / IT / RF / RG 단계별 집계 |

도구:

- **C++**: gcov / lcov (`cpp/build-coverage`)
- **Java**: JaCoCo (Maven `jacoco:report`)
- **Python**: pytest-cov

스프린트 기록 템플릿·릴리스 품질 게이트는 `docs/defect_report.md` §3.4~§3.5를 따른다.

## 6. (선택) GitHub Issues 연동

라벨 체계(`severity:*`, `item:*`, `phase:*`), Issue 본문에 §2 템플릿 적용, PR `Fixes #NNN` → CI → QA `verified` → Close 흐름을 문서화했다. Issues 미사용 시 `defect_list.md`만으로도 추적 가능하다.

## 7. 현재 상태

- 테스트: `27/27` Green (`ctest --test-dir build --output-on-failure`)
- Open Critical/Major: 0 (DEF-001~004 수정·검증 완료)
- 커버리지: `build-coverage` 빌드 후 §3.3 C++ 절차로 측정 권장
